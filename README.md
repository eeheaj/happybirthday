# Mom’s 52nd Birthday

A candlelit 3D cake and a shared scrapbook of birthday wishes. Plain HTML, CSS and JavaScript with three.js, Netlify Functions, and Netlify Blobs.

## The two links

- **Mom:** `https://YOUR-SITE.netlify.app/`
- **Contributors:** `https://YOUR-SITE.netlify.app/write`

The original `/#write` link also works. Hold anywhere on the cake screen (or hold Space/Enter on the blow button) to extinguish the candles. After smoke and confetti, the scrapbook opens automatically. Drag or scroll to explore; tap a piece to read its message. Keyboard users can Tab between pieces and Escape to close overlays.

Contributors enter their name and send text, a photo, a pasted sticker, or a doodle. The scrapbook checks for new wishes every five seconds while visible. This is polling, not a WebSocket subscription.

## Deploy to Netlify

1. Push this project to a Git repository.
2. In Netlify, import that repository as a new project.
3. Keep the settings in `netlify.toml`: **build command** `npm run build`, **publish directory** `public`, **functions directory** `netlify/functions`.
4. Deploy, then share the two links above using your assigned site address.

No database credentials or environment variables are required for a standard Netlify deployment. The Functions runtime supplies access to site-scoped Blobs stores. Use a Git deployment or the Netlify CLI; uploading only `public` through a static drag-and-drop deployment will omit the backend.

Alternatively, after `npm install` and `npm run build`, run `npx netlify login`, `npx netlify init`, and `npx netlify deploy --build --prod` from this directory.

## Run locally

Requires Node.js 22 or newer.

```sh
npm install
npm run build
npm run dev
```

Open `http://localhost:8888/` and `http://localhost:8888/write`. Netlify Dev provides local Functions and Blobs emulation; local wishes are separate from production. A plain static server cannot save wishes. On PowerShell installations that block npm scripts, use `npm.cmd` instead of `npm`.

## Data and access

This is a shared-link birthday card: **anyone who has the website address can read the scrapbook and send wishes.** The two links are different views, not different permission levels. Search indexing is discouraged, but this is not authentication. Keep the address within your intended group.

A random HttpOnly cookie identifies each contributor’s browser for one year. No sign-in is required. Clearing cookies or changing devices creates a new contributor thread; already submitted wishes remain in Mom’s scrapbook. Names belong to individual notes, so changing your name does not rename old messages.

`birthday-notes` stores one JSON record per submission. `birthday-images` stores its optional picture, preserving transparency. Server-generated timestamps, conditional writes and stable retry IDs prevent concurrent submissions overwriting notes or a retried request adding duplicates. Names are limited to 60 characters and messages to 1,500. Uploaded images are capped at 2 MB after browser resizing; source files above 20 MB are rejected. Unsupported HEIC files should be converted to JPG/PNG. Animated uploads become still images.

The API validates input, checks image signatures, rejects cross-origin writes and applies a Netlify IP/domain request limit. This is intended for a small family event, not a public social network. Anonymous identity is not a verified person, and the earlier frontend-only 40-note limit has been removed. Netlify plan usage limits still apply.

Production records persist across deployments. In Netlify’s Blobs UI, export/download the two stores to preserve a keepsake. Remove unwanted note records there; their image can be deleted separately using its `img.id`. A failed write after an image upload can leave an unused image; it is safe to remove images not referenced by any note. Deploy previews on the same Netlify site use the same site-scoped stores, so use a separate site for isolated staging.

## Verification

```sh
npm test
npm run build
npm run test:browser
```

The browser test starts its own local test server with in-memory stores and exercises the real API handler. It requires Playwright’s Chromium (`npx playwright install chromium`) or an installed Chrome/Edge. It does not create production wishes. Screenshots are written to ignored `test-results/`.

With `npm run dev` running, `npm run test:netlify` additionally checks the actual Netlify Functions and Blobs emulator, including image storage and the `/write` routes. This creates one test wish in local storage only.

Reference: [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/) and [Functions API](https://docs.netlify.com/build/functions/api/).
